# RepVane — full UI/UX audit & target spec (2026-09-28)

**Author:** ux-designer stream (F3), batch "user findings 0928".
**Ask:** "let the UI/UX check the whole pages and the buttons and make it a real web app like our competitors."
**Competitors referenced:** Hevy, Strong, Fitbod, JEFIT, MyFitnessPal (general, stable patterns — bottom tab nav, one-thumb set logging, big sticky primary action, calendar heat-map, exercise video/GIF demos; not a fresh web-search pull).

## 0. Method & scope

- **Live app:** https://gym-app.cloider.app, walked with Playwright at 390×844 (mobile) and 1440×900 (desktop), EN/LTR and AR/RTL, anonymous mode only (no accounts created, no real data submitted, per instructions).
- **Signed-in-only screens** (Profile, Notifications panel, full multi-day plan, Coach chat, Workout Builder) were **not** live-screenshotted — reaching them needs a real account or API mocks, which this pass didn't stand up. They're evaluated from source instead (`header.js`, `notifications.js`, `profile.js`, `workout-builder.js`, `calendar.js`, `styles.css`) and cross-checked against `ROADMAP-PROGRESS.md`'s own W1-A/W1-B smoke-test notes. Flagged inline wherever a finding is code-derived rather than screenshot-confirmed.
- **Orientation:** `graphify explain/query` over `graphify-out/graph.json` (commit `a2980500` = current `origin/main`), then targeted reads of `index.html`, `ui.js`, `app.js`, `styles.css`, `workout-builder.js`, `header.js`, `notifications.js`, `profile.js`.
- **Screenshots:** `docs/ux/screens/01…10` (this worktree). Referenced as **[S1]**…**[S10]** below.
- **Not duplicated here** — already owned by other in-flight streams, only noted where this audit's evidence adds a concrete detail they should see:
  - `fix/user-findings-0928` (frontend): builder scroll-jump, per-day muscle rule, recommended badge+filter, sticky selected day, chat focus+typewriter, legacy chooser, 4-day plan rewrite.
  - `feat/rebrand-teal` (logo-designer): teal `#0B7A75` "Dial Vane" brand + icons.

## 2. Screen-by-screen notes

**Onboarding / first run** — Two-step reveal (Start → choices) is a good pattern, low cognitive load. Copy is honest and short. Issues: P0-2, P0-3, P2-1.

**Legacy plan chooser** — Not reached in this pass's anon-mode walkthrough (anon mode correctly skips it, confirmed live), but confirmed still the default path for new signed-in accounts by reading `app.js:1286-1293`. See P1-1.

**Sign-in (Google/email/OTP)** — Onboarding's own flow is complete and consistent (Google, email/OTP, anon, "why sign in?" disclosure — good trust pattern). The *other* two sign-in surfaces (Plan gate, Coach gate) regress to Google-only. See P1-2.

**Home / today's workout (Plan tab)** — Strong bones: calendar strip with today highlighted, workout timer, warm-up card with its own video, per-exercise sets/reps/rest/video, "no log yet" empty state, sign-in-to-unlock card, reset-checklist escape hatch. This is close to Hevy/Strong's core loop already. The problems are all in the details: FAB overlap (P0-1), tap targets (P0-4), input truncation (P1-9), native confirm (P1-8).

**AI Coach (anon)** — Clean single-card teaser, but: Google-only gate (P1-2), vendor name exposed (P1-3), and a large dead zone of empty vertical space below the card down to the nav bar — the screen reads unfinished rather than intentionally minimal.

**More / settings** — Functionally complete (Plan, Program, Language, Sync, Training days, PWA-install tip). Carries the legacy gender toggle (P1-1) and the Google-button locale bug (P0-3).

**Profile & notifications (code review only, not live-tested)** — `header.js`/`profile.js`/`notifications.js` are recently rebuilt (PR #42, Opus-reviewed) and already handle: cached `/me`, Arabic byte-length validation, streak/photo caching, relative-time i18n via `Intl.RelativeTimeFormat`, focus-visible on notif items and profile fields. No new issues found beyond the open follow-up already logged in `ROADMAP-PROGRESS.md` (gym-be `validateProfile` should count runes, not bytes). Recommend a live pass once accounts/mocks are available, since this audit could only read the source.

**Workout builder (code review only)** — `workout-builder.js` header comments confirm the drag-and-drop + per-muscle-shape enforcement design is sound; the scroll-jump bug it references is already the subject of `fix/user-findings-0928`, not duplicated here.

**Calendar** — `styles.css` shows a full month modal (`#calendarModal`) with day detail, prev/next month, weekday row — not live-tested (reached via the "expand calendar" icon, which is itself under the 44px minimum, see P0-4).

**RTL / Arabic** — Overall RTL support is more careful than average: bottom-nav tab order visually mirrors (Plan ends up on the reading-start side), both FABs correctly reposition to the mirrored corner, `[dir="rtl"]` overrides exist for margins/expand-button position. The real gaps are translation *coverage* (P1-7) and the Google-button locale bug (P0-3), not RTL layout mechanics.

**Desktop (1440×900)** — See P0-2, P2-5.

## 3. Competitor pattern check (used to sanity-check §5, not a survey)

- **Hevy / Strong**: 4-5 icon-only bottom tabs (Workout/Home, Exercises, History, Profile), one unmissable primary "Start Workout" action, rest timer as a persistent bottom sheet during a session, superset/reorder via drag handles, one-thumb weight/rep steppers sized for gym use.
- **Fitbod**: calendar/heatmap-driven home, "why this exercise" rationale surfaced inline, muscle-recovery visualization.
- **JEFIT**: heavier exercise database + community layer, more desktop-web investment than the others.
- **MyFitnessPal**: diary-style logging, a large circular "+" FAB as the one and only floating action (never more than one at a time), barcode/quick-add for low-friction entry.

RepVane's Plan-tab bones already match this family closely. The gap is polish (P0-4, P1-6), one-FAB discipline (P0-1/P1-4 — MyFitnessPal's rule of "exactly one FAB" is the right target), and desktop not being an afterthought (P0-2).

## 4. Target design system spec

### 4.1 Color tokens

Keep the app **dark-first** (matches the gym/night-training context, matches Hevy/Strong/Fitbod defaults, matches the sunk cost in the current dark visuals) and resolve the `--paper` naming collision from P2-2 by renaming the *text* tokens rather than overloading the brand's paper background color onto them.

```css
:root{
  /* brand */
  --teal-600:#0B7A75;      /* primary accent — was --rust/--accent */
  --teal-500:#12968F;      /* hover/active state, +12% lightness */
  --teal-700:#075753;      /* pressed state, -15% lightness */
  --teal-soft:#0f2e2c;     /* accent-tinted surface, e.g. active pills/badges */
  --ink-900:#14161B;       /* brand ink — reserved for the light theme (below) */
  --paper-50:#F3F0E8;      /* brand paper — reserved for the light theme (below) */

  /* dark theme (default) surfaces */
  --bg:#0d1117; --bg-alt:#141b24; --panel:#161d27; --panel2:#1e2733;
  --line:#26303d;

  /* dark theme text (renamed from --paper/--paper-dim to avoid the brand clash) */
  --text-100:#eef2f7;      /* was --paper */
  --text-60:#9fb0c3;       /* was --paper-dim */

  /* semantic */
  --accent:var(--teal-600); --accent-hover:var(--teal-500); --accent-active:var(--teal-700);
  --success:#3fb950; --success-soft:#123320;
  --danger:#e5484d; --danger-soft:#3a1416;
  --warning:#e8a33d;
  --glow:rgba(11,122,117,0.18);

  /* geometry (see 4.3/4.4) */
  --radius-sm:8px; --radius-md:12px; --radius-lg:20px; --radius-pill:999px;
  --dur-fast:.14s; --dur-med:.28s; --ease:cubic-bezier(.22,.61,.36,1);
  --elev-1:0 2px 10px rgba(0,0,0,.28);
  --elev-2:0 14px 40px rgba(0,0,0,.45);
}

/* Optional future light theme — brand's paper/ink pairing, behind a manual
   toggle or prefers-color-scheme:light, NOT the default. Ship after dark
   theme is fully teal. */
:root[data-theme="light"]{
  --bg:var(--paper-50); --bg-alt:#ece7db; --panel:#ffffff; --panel2:#f7f4ec;
  --line:#ddd6c4; --text-100:var(--ink-900); --text-60:#5b5d62;
}
```

Keep the existing **female palette override** pattern (`:root[data-plan="female"]`) but reduce it to accent-only once the plan chooser stops framing plans by sex (P1-1) — it can become a purely cosmetic "theme" choice a user opts into, not a consequence of a gender field.

### 4.2 Type scale (replaces the 21 ad-hoc sizes, P1-6)

| Token | px | Use |
|---|---|---|
| `--text-xs` | 11 | captions, badges, timestamps |
| `--text-sm` | 12.5 | secondary labels, meta rows |
| `--text-base` | 14 | body copy, list items |
| `--text-md` | 16 | primary buttons, emphasized body |
| `--text-lg` | 19 | card/section titles |
| `--text-xl` | 23 | screen titles (h1) |
| `--text-2xl` | 28 | hero numbers (session timer) |
| `--text-3xl` | 34 | (reserved — marketing/desktop only) |

Font weight stays binary: 700 (semibold, default UI weight) / 900 (headings, active nav, big numbers) — already the de facto pattern, just formalize it.

### 4.3 Spacing scale

4px base: `4, 8, 12, 16, 20, 24, 32, 40, 48` — `styles.css` already mostly lands on these by accident (8/12/14/16/18/20/24 appear constantly); the only outliers to fix are the odd 14/18px paddings that should round to 12/16/20.

### 4.4 Radii & elevation

- `--radius-sm:8px` — inputs, small chips, icon buttons.
- `--radius-md:12px` — cards, exercise rows.
- `--radius-lg:20px` — sheets/modals, onboarding card.
- `--radius-pill:999px` — tab pills, plan-toggle segments.
- `--elev-1` — resting cards. `--elev-2` — anything overlaying content (modals, sheets, FABs' own shadow, not the content behind them).

### 4.5 Buttons — variants, sizes, states

All interactive controls: **`min-height:44px`**, **`min-width:44px`** for icon-only buttons (P0-4).

| Variant | Background | Border | Text | Use |
|---|---|---|---|---|
| Primary | `--accent` filled | none | white, 700 | one per screen — Start Workout, Sign in, Save plan |
| Secondary | transparent | 1px `--line` | `--text-100` | Continue with email, Back, Rest |
| Tertiary/ghost | transparent | none | `--text-60`, underline on hover | Reset checklist, "Why sign in?", links |
| Destructive | transparent → `--danger` on confirm step | 1px `--danger` | `--danger` | delete saved plan, sign out (rare enough to not need a filled treatment) |
| Icon button | transparent / `--panel2` on hover | none | — | expand, close, video, calendar-expand — **44×44 hit area even if the glyph is 20px** |

States every variant needs, explicitly, not left to browser defaults:
- `:hover` (desktop only — gate behind `@media (hover:hover)`)
- `:active` — existing `scale(.9-.98)` press feedback is good, keep it
- `:focus-visible` — **mandatory 2px `--accent` outline, 2px offset, on every one of the above** (currently inconsistent, P1-5)
- `:disabled` — 40% opacity, no pointer events, no press animation
- loading — spinner replaces label, button stays same width (no layout shift)

### 4.6 Core components to formalize

- **Bottom tab bar** (`#appNav`): icon 22-24px, label 11px, active = accent fill + drop-shadow (already good) — just raise the 900px breakpoint's target to apply everywhere including onboarding (P0-2).
- **Exercise card**: checkbox (raise to 24px visual / 44px hit area) → name → sets/reps/rest meta row → wt/rep inputs (widen, P1-9) → Save/Rest/Video row (44px, P0-4) → last-log caption.
- **FAB**: exactly one visible at a time per screen (MyFitnessPal rule, §3) — resolve P0-1/P1-4 by scoping, not by restyling.
- **Toast / undo bar**: new component needed to replace native `confirm()` (P1-8) — bottom-anchored, above the tab bar, auto-dismiss 5-6s, single "Undo" action.
- **Empty / loading / error / offline states**: audit didn't find a consistent skeleton-loading pattern in `styles.css` (search for `skeleton`/`shimmer` returned nothing) — recommend one shared `.skeleton` shimmer block reused by Plan (exercise list), Coach (history), Calendar (month grid) instead of each screen inventing its own "loading…" text.

## 5. Navigation / IA proposal

Keep the existing 3-tab-plus-avatar-menu model — it's already close to right and matches the competitor set — but tighten it:

```
Bottom tabs (unchanged):  [ Plan ]  [ Coach ]  [ More ]
Top-right (signed-in only, unchanged): streak · bell · avatar → Profile
```

Recommendation: **don't add a 4th tab.** Calendar stays a modal reached from the Plan screen (already the case); food logging (queued) should land as a section *within* the Coach tab or its own modal reached from Plan, not a new tab — Hick's law: 3 tabs is the right number for this app's actual daily jobs (train today, ask the coach, adjust settings), a 4th tab for an occasional action dilutes it.
